# Testing

> The three suites that cover the plugin, what each one exercises, how to run them, and the i18n parity check.

The PHP and browser suites run against the disposable wp-env environment; Vitest runs in jsdom without WordPress. The PHP and browser suites target the **tests** instance on port **8889** and never touch the development instance on 8888. The Playwright config rejects a `WP_BASE_URL` containing `:8888`, and tests mode of the demo seeder also refuses the development instance.

Start wp-env first (`npm run dev`, or `npx wp-env start`). `npm test` does not start it.

## Suite overview

| Suite      | Command            | Environment                              | Covers                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------- | ------------------ | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vitest     | `npm run test:js`  | jsdom, no WordPress                      | Waymark JS Viewer and Editor API, the image viewer, gallery integration and viewer navigation map sync, default Map view fallbacks, editor i18n, description sanitisation and XSS, i18n escaping, locale formatting, stable type keys and editor console regressions.                                                                                                                                                                                                   |
| PHPUnit    | `npm run test:php` | wp-env tests container, port 8889        | Settings (including repeatable values), Map config defaults, Map data and guards, revisions, shortcode and Collection rendering, attachment metadata, demo image EXIF, requirements, release metadata, stable keys and i18n.                                                                                                                                                                                                                                            |
| Playwright | `npm run test:e2e` | Chromium against `http://localhost:8889` | Admin menu, Settings markup, labels and repeatable rows, marker icon UI, stable type keys, responsive admin layout, RTL layout, locale formatting, the Map editor smoke test and its jQuery Migrate warning gate, admin Map editor height, Map editor marker image hover and crop behaviour, info window re-fit on zoom, guaranteed initial map view, image viewer navigation map sync, image viewer layout at desktop and phone widths, and deterministic screenshots. |

Run one suite with its script, or all three in order with `npm test` (`test:js`, then `test:php`, then `test:e2e`).

## Vitest

Config: [`vitest.config.mjs`](../vitest.config.mjs). The environment is jsdom, the setup file is [`waymark-js/tests/setup.js`](../waymark-js/tests/setup.js), and the include pattern is `waymark-js/tests/**/*.test.js`.

The setup loads Leaflet and the bundled plugins, then evaluates the Waymark JS sources in order (`Waymark_Map`, `Waymark_Lightbox`, `Waymark_Map_Viewer`, `Waymark_Map_Editor`, `Waymark_Map_Factory`) into the global scope. The tests under `waymark-js/tests/docs/` mirror the library's documented API chapters; the remaining specs cover XSS and sanitisation, the image viewer, gallery integration and viewer navigation map sync, default Map view fallbacks, editor i18n, i18n escaping, locale formatting, stable type keys and editor console regressions.

The image viewer specs cover the `on_navigate` contract — fired by `prev()` and `next()` after `show_index()`, and not by `open()` — and `sync_map_to_lightbox()` for a Marker pan, a polyline bounds fit and the no-op when the item or layer is missing. They also cover `description_to_text()` — block boundaries and `<br>` becoming spaces, entity decoding, whitespace collapsing, an allowed link reduced to its text, and missing input returning an empty string — and the primitive's caption, which writes the item's description as text rather than markup and hides the element when an item has none.

The console-regression spec builds Marker and Line content, boots the editor and toolbar, and invokes the Editable handlers directly. It covers deprecated jQuery shorthands, `.prop()`-based selection state, per-layer defaults copied with `Waymark.get_data_defaults()` and the circle-only `getRadius()` path, so those regressions fail in jsdom rather than only in a browser.

## PHPUnit

Config: [`phpunit.xml.dist`](../phpunit.xml.dist). The suite is `tests/phpunit`, the bootstrap is [`tests/phpunit/bootstrap.php`](../tests/phpunit/bootstrap.php), and PHPUnit runs inside the tests container:

```sh
npm run test:php
```

The command is `wp-env run tests-cli --env-cwd=wp-content/plugins/waymark-wp phpunit`. The bootstrap loads the WordPress test library bundled with wp-env and the plugin as WordPress would. It also loads the admin meta and revision classes explicitly, because `is_admin()` is false during the test bootstrap.

Prepare the container once after a fresh environment (`wp-env destroy`):

```sh
npm run test:php:setup
```

That installs PHPUnit ^9.6 and the Yoast PHPUnit polyfills in the tests container. `npm run test:php:lint` runs `php -l` over the plugin from inside the same container.

`WP_ENV_PHP_VERSION` and `WP_ENV_CORE` override the container versions, for example to run against the declared PHP and WordPress floor.

> [!NOTE]
> The PHP suite resets the tests database and deactivates the plugin and theme. The Playwright global setup heals that before the browser suite runs.

### Demo image fixtures

[`tests/phpunit/test-demo-image-exif.php`](../tests/phpunit/test-demo-image-exif.php) guards the demo photos used by the Playwright suite. It reads [`tests/fixtures/demo/image-metadata.json`](../tests/fixtures/demo/image-metadata.json), the single source of truth for each image's file, title, alt text, camera, capture time and GPS, and verifies the checked-in files carry the manifest's deterministic EXIF: camera make and model, capture timestamps, orientation `1`, and GPS coordinates that convert to the manifest's latitude and longitude.

The demo seeder reads the same manifest. Because `wp eval-file` is not an admin request, it registers [`Waymark_Admin::add_gps_exif`](../inc/Waymark_Admin.php) before sideloading, then asserts each attachment's `image_meta` has GPS coordinates matching the manifest, the manifest's camera model, and a capture timestamp. The GPS values follow each image's feature location in the demo Maps. Seeding the tests instance in tests mode always writes [`seed-output.json`](../tests/fixtures/demo/seed-output.json), which the specs use for IDs, permalinks and image URLs.

Dev mode is separate. `npm run dev` runs `seed:dev` after `wp-env start`, and `npm run seed:dev` runs it manually against the development container (`cli`, port 8888) — the only mode that accepts that instance. It seeds only an untouched instance and stops before the first write, logging `Skipping demo seed: <reason>.`, when the `waymark_demo_dev_seeded` marker is set, Waymark settings, Maps, Collections, the demo Page or demo media exist, the `waymark-demo` uploads directory is non-empty, or a post occupies a reserved ID from 100 to 119. A successful run sets the marker and never writes `seed-output.json`; the plugin uninstall clears the marker. Neither a bare `npx wp-env start` nor CI runs dev mode; the Playwright global setup still seeds the tests instance in tests mode. Reset the instance (`npx wp-env destroy`, then start it) to reseed. The read-only checks live in [`tests/fixtures/demo/seed-guard.php`](../tests/fixtures/demo/seed-guard.php).

### Release metadata

[`tests/phpunit/test-release.php`](../tests/phpunit/test-release.php) guards the version metadata that ties the plugin header to the distributed files. It requires a `MAJOR.MINOR.PATCH` version in [`Waymark.php`](../Waymark.php) and [`package.json`](../package.json), and asserts that `readme.txt`'s `Stable tag` matches `package.json`'s `version`, because `grunt sync_version` writes both from the header in one step. It also requires a `= X.Y.Z =` section in the `readme.txt` `== Changelog ==` for the header version, and checks that the generated [`readme.md`](../readme.md) carries the same `**Stable tag:**` value and `### X.Y.Z ###` changelog heading.

The tests deliberately do not require every file to hold the same version. During release preparation the header is bumped first while `package.json` and `Stable tag` still name the previous release; `grunt sync_version` rewrites them from the header during the CI release run. The ordering is asserted rather than equality: the derived files may lag the header but must never lead it (`version_compare( package, header, '<=' )`), so changing this to strict equality would break the gate on every release. `package-lock.json` is not touched by `sync_version` and is intentionally not asserted.

## Playwright

Config: [`playwright.config.js`](../playwright.config.js). `testDir` is `tests/e2e`, Chromium only, one worker, no retries, and a 15-second test timeout. `baseURL` is `WP_BASE_URL` or `http://localhost:8889`.

Failure artefacts go to the `outputDir` configured in [`playwright.config.js`](../playwright.config.js), a project-local temporary directory: traces are retained on failure and screenshots are taken on failure.

Global setup [`tests/e2e/global.setup.js`](../tests/e2e/global.setup.js) checks that the tests instance answers, reactivates the plugin and Twenty Twenty-Five, and reseeds the demo dataset before any spec runs.

The deterministic screenshot specs import the extended `test` from [`tests/e2e/fixtures.js`](../tests/e2e/fixtures.js), which provides the external-request guard, third-party asset stubs, motion and caret determinism, and tile record and replay. The legacy `map-editor.spec.js` intentionally uses live OSM tiles and does not import the harness; see [`tests/e2e/README.md`](../tests/e2e/README.md). It unmutes jQuery Migrate for the run and fails on its deprecation warnings as well as console and page errors.

[`map-view-defaults.spec.js`](../tests/e2e/map-view-defaults.spec.js) covers the guaranteed initial view. It opens the seeded `circle-only` and `empty-map` Maps and proves that a Circle-only Map loads and fits its Circle with valid bounds, that an empty Map renders at the Settings Default Centre/Zoom exposed as `map_options.map_default_latlng` and `map_default_zoom`, and that neither raises a console or page error. It imports the harness and stubs every basemap tile in memory, because the fallback view sits outside the frozen tile pack.

[`map-editor-height.spec.js`](../tests/e2e/map-editor-height.spec.js) covers the admin Map editor height. It proves the editor renders at the configured Map Height, follows a non-default setting, never drops below the 450px floor, and keeps its height across saving and dismissing the update notice. It imports the harness and stubs every basemap tile transparently.

[`map-editor-image-hover.spec.js`](../tests/e2e/map-editor-image-hover.spec.js) covers the Map Editor's Marker info-window image control. It re-enables motion, then proves that a Marker with no image URL keeps its 60px placeholder on hover, while a Marker with a non-square image grows from 60px to 240px and crops to fill with `object-fit: cover`. The hover animates width, height and left over 0.4s, and `prefers-reduced-motion: reduce` collapses the transition. It imports the harness and stubs every basemap tile transparently.

[`elevation-profile.spec.js`](../tests/e2e/elevation-profile.spec.js) covers elevation detection. It proves an all-zero Line keeps a flat profile with a centred transform origin and a finite hover indicator, and that a Line with real elevation shows its profile without the `zero-elevation` class. It imports the harness and stubs every basemap tile in memory, because neither Map is part of the frozen tile pack.

[`image-lightbox.spec.js`](../tests/e2e/image-lightbox.spec.js) covers the image viewer against real dialog, CSS and Leaflet behaviour: popup image markup, opening at the large URL, keyboard and button navigation, every close path, the single-image and gallery cases, map syncing on navigation, and the caption description. The description case gives a seeded feature an HTML-marked description containing an entity and asserts the caption shows the decoded plain text with no child elements, then steps to a feature without a description and back to prove the element hides and returns. It also pins the description's computed full-width row, centred text, `65px` maximum height and vertical scrolling, including a long description that must scroll rather than grow the dialog. The layout specs pin the dialog's computed `position` to `fixed` and assert that it is centred on both axes within 2 px, contained by the viewport and free of horizontal page overflow. The default viewport case checks centring and containment; a 390 × 844 phone case repeats those checks and adds `44 × 44` controls and a `14px` caption. The sync test opens the viewer on a LineString photo and steps to the two Markers, polling until the Map centre settles on each feature and checking that the first Marker's Info Window is open. The spec serves every basemap tile from memory, because the gallery's zoom sits outside the frozen tile pack.

### Fixtures

- [`tests/fixtures/demo/seed.php`](../tests/fixtures/demo/seed.php) — demo seeder for Maps, Collections, Media, Meta, Settings and the demo page. Tests mode resets and writes the fixture; dev mode seeds only an untouched instance.
- [`tests/fixtures/demo/seed-guard.php`](../tests/fixtures/demo/seed-guard.php) — read-only dev-mode freshness checks.
- [`tests/fixtures/demo/seed-output.json`](../tests/fixtures/demo/seed-output.json) — generated IDs, slugs, permalinks and image URLs used by the specs; written by tests mode only.
- [`tests/fixtures/demo/image-metadata.json`](../tests/fixtures/demo/image-metadata.json) — manifest for the demo photos, shared by the seeder and the PHPUnit EXIF test.
- `tests/fixtures/demo/tiles/` — frozen basemap tiles replayed by the deterministic specs.
- [`tests/fixtures/route.geojson`](../tests/fixtures/route.geojson) — canonical route fixture used to build the demo Map.
- [`tests/e2e/fixtures.js`](../tests/e2e/fixtures.js) — seed lookups, URL helpers and the deterministic test harness.

The WordPress.org screenshot captures are part of this suite. `npm run screenshots` recaptures them, publishes them to `.wordpress-org/` and refreshes the `readme.md` hashes; `npm run screenshots:check` recaptures and verifies the published files and hashes without republishing. See [`tests/e2e/README.md`](../tests/e2e/README.md).

## Help site

The help site has no dedicated automated test suite. Its checks are:

- `cd help && npm run generate` — builds the static site.
- Browser smoke tests of the pages you changed, under both `/` and `/waymark-wp/`.

The live map demos derive their shared data from [`port-hardy-to-cape-scott.geojson`](../help/public/assets/geo/port-hardy-to-cape-scott.geojson), imported at build time with `?raw` by [`help/app/data/demos/fixtures.ts`](../help/app/data/demos/fixtures.ts); the homepage demo instead fetches the published GeoJSON at runtime. No automated suite asserts their rendering.

## Internationalisation check

`npm run i18n:check` runs [`scripts/i18n-check.mjs`](../scripts/i18n-check.mjs) and enforces the key-parity contract for strings shared by PHP, the Waymark JS library and the help-site demos. It is a source check, not a test suite, and it does not run as part of `npm test`.

| Source     | File                                                                          | Role                                                                                                     |
| ---------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| PHP        | [`inc/Helpers/Waymark_Lang.php`](../inc/Helpers/Waymark_Lang.php)             | `Waymark_Lang::get_js_lang()` is the source of the strings injected into `waymark_user_config.language`. |
| JavaScript | [`waymark-js/src/js/Waymark_Map.js`](../waymark-js/src/js/Waymark_Map.js)     | The `language` defaults let the library run without WordPress.                                           |
| Help site  | [`help/app/data/waymarkUserConfig.ts`](../help/app/data/waymarkUserConfig.ts) | Mirrors the defaults for the live demos in `help/content/`.                                              |

The command extracts the keys and values from each source and fails when:

- a key is missing from any of the three sources;
- a key that appears in more than one source has a different value;
- a `waymark_php_lang` key localised in [`inc/Admin/Waymark_JS.php`](../inc/Admin/Waymark_JS.php) is never read in [`assets/js/admin.js`](../assets/js/admin.js), or vice versa.

It prints the key count for each source and exits non-zero with a list of problems. It checks the English source defaults, not translated `.po` files or the generated POT. The parser identifies the PHP array by `function get_js_lang` and the JavaScript defaults by a `language` block containing `action_fullscreen_activate`; keep those anchors in place when editing.

### Adding or renaming a string

- Map UI strings belong in all three sources, with the same English value in each. PHP wraps the value in a gettext helper; the JS and help-site copies are plain defaults.
- Admin-only strings belong in the `waymark_php_lang` array in `inc/Admin/Waymark_JS.php` and must be read as `waymark_php_lang.<key>` in `assets/js/admin.js`. Do not add them to the three map-language sources unless the map library also needs them.
- Rename a key in every place it appears, run `npm run grunt` to refresh `languages/waymark.pot`, then run `npm run i18n:check`.
- Do not translate keys. Stable Type, Meta and group keys are internal identifiers and are outside this contract; translated labels are separate.

CI runs the check in the `test` job of [`.github/workflows/tests.yml`](../.github/workflows/tests.yml) before the suites.

## Running everything

```sh
npm test
```

This runs the three suites in sequence and stops on the first failure. In CI, [`.github/workflows/tests.yml`](../.github/workflows/tests.yml) runs the JavaScript suite, PHPUnit and Playwright on current WordPress with PHP 8.5, repeats PHPUnit on the WordPress 6.4 and PHP 8.3 floor, and validates the video deliverables. It also runs `npm run i18n:check`, `npm run readme:check` and confirms that the generated `readme.md` is up to date.

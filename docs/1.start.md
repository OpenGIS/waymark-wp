# Getting started

> Set up the plugin, run both development loops, and find the commands used most often.

## Environment

Waymark is a WordPress plugin. The local environment is provided by `@wordpress/env` (wp-env), so Docker is required in addition to Node.js and npm.

| Requirement      | Version and notes                                                                                                             |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Node.js          | 24 is used by CI and the release workflows. The root [`package.json`](../package.json) does not declare an `engines` range.   |
| npm              | Installed with Node.js.                                                                                                       |
| Docker           | Required by wp-env.                                                                                                           |
| PHP              | 8.3 minimum ([`Waymark.php`](../Waymark.php), [`readme.txt`](../readme.txt)). [`.wp-env.json`](../.wp-env.json) pins PHP 8.3. |
| WordPress        | 6.4 minimum; 7.1 tested.                                                                                                      |
| Help site        | Node.js 24.15.0 or newer ([`help/package.json`](../help/package.json)).                                                       |
| Video (optional) | ffmpeg and ffprobe; see the [video pipeline](3.video-pipeline.md).                                                            |

`WP_ENV_PHP_VERSION` and `WP_ENV_CORE` override the wp-env PHP and WordPress versions, which is useful for testing the declared floor or a release candidate.

## First-time setup

```sh
npm install
npm run dev
```

`npm run dev` starts wp-env and then runs `grunt watch`. The development site is <http://localhost:8888/wp-admin> (`admin` / `password`); the printed summary also lists MySQL at `127.0.0.1` (`root` / `password`). Because [`.wp-env.json`](../.wp-env.json) enables the tests environment, wp-env also starts the disposable tests instance on port 8889.

In a second terminal, prepare the PHP test container once after a fresh environment:

```sh
npm run test:php:setup
```

Then run the suites with `npm test`. See [Testing](4.testing.md) for what each suite covers.

### Help site

The user-facing help site is a separate Nuxt application in [`help/`](../help/):

```sh
cd help
npm ci
npm run sync-assets
npm run dev
```

It runs at <http://localhost:11003>. `help/content/` holds the Markdown pages and `help/app/` the Nuxt application. `sync-assets` copies the compiled Waymark JS/CSS from the plugin into `help/public/assets/`, so rebuild those first if their sources have changed. The help site requires Node.js 24.15.0 or newer. Its published base URL is `/waymark-wp/`; locally it uses `/` unless `NUXT_APP_BASE_URL` is set. The plugin's **Waymark > Help** menu item opens the published site through `Waymark_Helper::site_url()`.

### Help content

User-facing pages live in `help/content/` as Markdown. Nuxt Content maps the file path to the page URL (`help/content/tutorials/drawing-a-route.md` becomes `/tutorials/drawing-a-route/`), so each directory needs an `index.md` landing page and published slugs should stay stable.

Every page starts with frontmatter:

```yaml
---
title: Drawing a Route
description: In this tutorial we will use Waymark to create a Route.
---
```

`title` is the page heading and browser title. `description` is rendered as the lead paragraph and used for the meta description; inline HTML is allowed and tags are stripped for SEO. No other frontmatter is required. The right-hand "On this page" outline is built from `##` and `###` headings, so use those levels for structure rather than bold text.

Navigation has three parts:

- The top navigation is fixed in [`help/app/components/AppNav.vue`](../help/app/components/AppNav.vue). A new top-level section needs a link there and, if it uses a card grid, a new `DocCardSection` member and section data in [`help/app/data/docCards.ts`](../help/app/data/docCards.ts).
- Section landing pages usually embed `::doc-card-grid{section="tutorials"}`, and the cards come from `help/app/data/docCards.ts`. Add or update a card when adding a page to a card-driven section.
- Breadcrumbs and previous/next links are derived from the content tree by [`help/app/pages/[...slug].vue`](../help/app/pages/[...slug].vue). Keep the directory structure meaningful and use an `index.md` for each section.

Use British English, sentence-case headings, and root-relative links with a trailing slash (`/customising/settings/`), matching the existing pages.

#### Content components

- `::docs-figure{src="/assets/img/example.png" alt="" caption="..."}` renders a screenshot from `help/public/assets/img/`. It also accepts `srcset`, `sizes`, `width`, `height` and `loading`.
- `::video-figure{src="/assets/video/<id>.mp4" poster="/assets/video/posters/<id>.jpg" captions="/assets/video/captions/<id>.en.vtt" label="..."}` renders an MP4 with a poster and a WebVTT caption track. `label` is the accessible name; `caption` adds a visible figcaption. Wrap several in `::video-grid` and add one colon to the inner fences (`:::video-figure`). `captions` also accepts an array of `{ src, srclang, label, default }` tracks.
- `::callout{type="warning" title="Back up first"}` renders an info or warning callout; the body follows as a nested block.
- `::map-demo{demo="markers" height="640"}` renders a live demo. Each demo needs a data module in `help/app/data/demos/` and an entry in [`MapDemo.vue`](../help/app/components/content/MapDemo.vue), so adding one is code work rather than content-only work.
- `::settings` with nested `:::setting{title="Map Height" type="text" default="450"}` renders the definition list used on the Settings page.

#### Assets and videos

Static images live in `help/public/assets/img/`; reference them as `/assets/img/...`. The Waymark JS and CSS used by the demos are generated: run `npm run grunt` at the repository root, then `npm run sync-assets` in `help/`. The script is [`help/scripts/sync-waymark-assets.mjs`](../help/scripts/sync-waymark-assets.mjs); it copies `waymark-js/dist/{css,js,fonts,images}` and `assets/css/front.min.css` into `help/public/assets/`. Those copies are gitignored, so edit the sources rather than the copies.

Video delivery files live in `help/public/assets/video/`: `<id>.mp4`, `posters/<id>.jpg`, `captions/<id>.en.vtt`, `transcripts/<id>.md` and `manifest.json`. The source scenarios and narration are under `scripts/video/`; see [Video pipeline](3.video-pipeline.md) and the [runbook](../scripts/video/README.md). After adding or changing an embed, run `npm run video:validate` from the repository root; it checks the committed assets and every `/assets/video/...` reference in the content. Then run `cd help && npm run generate` and smoke-test the page under both `/` and `/waymark-wp/`.

## Two development loops

| Loop      | Command                  | What runs                                                                                                                                |
| --------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Plugin    | `npm run dev`            | wp-env on 8888 plus `grunt watch`. Watches the plugin LESS and JavaScript, `readme.txt`, and the Waymark JS JavaScript and LESS sources. |
| Help site | `cd help && npm run dev` | Nuxt development server on 11003.                                                                                                        |

`grunt watch` does not rebuild `languages/waymark.pot`; run `npm run grunt` after changing translatable strings. The test suites use the same wp-env instances; see [Testing](4.testing.md).

## Key commands

| Command                     | Purpose                                                                                                           |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `npm run dev`               | Start wp-env and run `grunt watch`.                                                                               |
| `npm run grunt`             | Full asset build: CSS, JavaScript bundles, Waymark JS `dist`, the translation template and generated `readme.md`. |
| `npm run grunt:watch`       | Watch and rebuild the asset groups listed above.                                                                  |
| `npm run i18n:check`        | Check PHP, JavaScript and help-site language-default parity.                                                      |
| `npm test`                  | Run all three test suites in sequence.                                                                            |
| `npm run test:js`           | Run the Vitest suite only.                                                                                        |
| `npm run test:php`          | Run PHPUnit in the wp-env tests container.                                                                        |
| `npm run test:e2e`          | Run the Playwright suite against the tests instance.                                                              |
| `npm run test:php:setup`    | Install PHPUnit and the Yoast polyfills in the tests container (one-off).                                         |
| `npm run test:php:lint`     | PHP syntax check inside the tests container.                                                                      |
| `npm run dist`              | Build a local, CI-faithful plugin zip.                                                                            |
| `npm run screenshots`       | Recapture and publish the WordPress.org screenshots and `readme.md` hashes.                                       |
| `npm run screenshots:check` | Verify the published screenshots and `readme.md` hashes without republishing.                                     |
| `npm run readme:check`      | Verify the generated `readme.md` screenshot hashes without running the browser suite.                             |
| `npm run video:validate`    | Validate the committed screencast deliverables.                                                                   |

## Where things live

- [`Waymark.php`](../Waymark.php) — plugin header and bootstrap; the version lives here.
- [`inc/`](../inc/) — PHP: admin, front-end, objects and helpers. See [Architecture](2.architecture.md).
- [`assets/`](../assets/) — LESS sources (`assets/less/`) and compiled CSS/JavaScript (`assets/css/`, `assets/js/`).
- [`waymark-js/`](../waymark-js/) — the bundled map library; sources in `src/`, build in `dist/`.
- [`tests/`](../tests/) — PHPUnit and Playwright suites plus demo fixtures. Vitest tests live in [`waymark-js/tests/`](../waymark-js/tests/).
- [`help/`](../help/) — the user-facing Nuxt help site.
- [`scripts/`](../scripts/) — build, readme and video tooling.

# Video pipeline

> How the documentation screencasts are produced, and where to read the authoritative runbook.

The video tooling turns versioned scenario and narration files into the MP4s, posters, captions and transcripts used by the help site. It is separate from the plugin build.

- **Runbook:** [`scripts/video/README.md`](../scripts/video/README.md). Treat that file as authoritative for prerequisites, authoring rules, commands and delivery constraints; this page only points at it.
- **Scenarios:** [`scripts/video/scenarios/`](../scripts/video/scenarios/) — one JSON file per video, with matching narration under `scripts/video/narration/`.
- **Shared paths:** [`scripts/video/lib/paths.mjs`](../scripts/video/lib/paths.mjs) — derives the repository root, `help/public`, `help/content` and the delivery directory from one place.
- **Delivered assets:** [`help/public/assets/video/`](../help/public/assets/video/).
- **Source content:** [`help/content/`](../help/content/) embeds the videos with `video-figure` blocks.
- **Validation:** `npm run video:validate` is read-only and offline. It checks the committed assets against the manifest and confirms that every video path in the help content resolves.

The pipeline uses its own wp-env instance on port 11000, defined by [`scripts/video/wp-env.video.json`](../scripts/video/wp-env.video.json). Never record or seed against the development instance (8888) or the tests instance (8889).

`npm run video` runs narration synthesis, recording, build and validation for one scenario. The runbook lists the individual entry points (`video:tts`, `video:record`, `video:build`, `video:audit`, `video:doctor` and `video:new`).
